# Contributing to The Planetary Atlas

The Planetary Atlas is currently developed by invitation. Pull requests are for approved collaborators only.

## Collaboration access

- Maintainers invite collaborators when there is a defined piece of work to undertake.
- Collaborators should open a GitHub issue before beginning substantial work, unless a maintainer has already assigned one.
- External pull requests may be closed without review. This is a capacity and scientific-quality policy, not a judgment on the contributor.
- Public issues remain welcome for well-scoped bugs, data-source corrections, accessibility concerns, and research references. They are not a commitment to accept work or provide support.

## Working as an approved collaborator

1. Work from an assigned issue and keep its acceptance criteria current.
2. Create a focused branch; avoid mixing unrelated refactors and product changes.
3. Use TypeScript and TSX only. Do not add JavaScript or JSX source files.
4. Use Tailwind CSS 4 utilities only. Do not introduce raw CSS, CSS modules, styled components, or inline styles.
5. Preserve data provenance. Do not present derived, modelled, or artist-concept content as observation.
6. Run the relevant type checks, tests, and production build before requesting review.
7. Open a pull request only when the issue's acceptance criteria are met. Explain the evidence, tests, migration impact, and any unresolved scientific uncertainty.

## Data and scientific integrity

Changes that affect catalogue values, source ingestion, visualisations, descriptions of habitability, or external scientific claims require a source and an explicit account of the assumptions made. When in doubt, label content as unknown or modelled rather than inferring certainty.

## Security and sensitive reports

Do not open a public issue for a security vulnerability, credential exposure, or private user-data concern. Contact a maintainer privately through the repository owner's published contact channel instead.
